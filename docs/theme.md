Theme
===

[base16](https://github.com/tinted-theming/home) colour schemes drive everything, so the editor, terminal,
prompt and tools always match. There are two, one for each macOS appearance, and everything switches when
macOS does (System Settings → Appearance, or Auto at sunset). Both are `base16-everforest-dark-medium` for
now: no light scheme has been picked yet, so light mode looks like dark mode (`change_theme light` picks one).

What it is
---
Only two things know the actual colours; everything else uses the terminal's 16 ANSI colours and follows
along:

| Uses the scheme directly | Uses the 16 terminal colours |
|---|---|
| nvim (`tinted-vim` colour schemes) | tmux (status bar, popups, menus, copy mode), starship prompt, fzf, bat, delta, glow (`mdv`) |
| Ghostty (`config/ghostty/themes/base16-dark` and `base16-light`, generated) | file colours in eza, fzf-tab and completion (vivid's `ansi` theme) |

How a switch reaches each part:

| Part | Switches by |
|---|---|
| Ghostty | its own `theme = light:…,dark:…`: it watches macOS and changes the colours of every window at once |
| tmux, starship, fzf, bat, eza, … | nothing: they use the 16 colours, which Ghostty has just changed |
| nvim | Ghostty reports the change (DEC mode 2031), tmux passes it on, nvim asks for the background colour again and sets `'background'`; `lua/user/base16-vim/config.lua` then loads the scheme for it. A new nvim works out `'background'` the same way when it starts |

Text is Source Code Pro. Icons in eza, starship, nvim and the tmux status bar are Nerd Font glyphs, which
Ghostty draws from its built-in symbol font.

Switching schemes
---
1. Run `change_theme dark` or `change_theme light` (without an argument, the mode macOS is in now) and pick a
   scheme (every base16 scheme tinted-vim ships, a few hundred): it opens ready to type, best match first;
   `jj` for `j`/`k` ([picker keys](tmux.md#picker-keys)). It regenerates that mode's Ghostty theme from the
   scheme, using the standard base16 → ANSI mapping, and writes the scheme's name into nvim's list.
2. Reload Ghostty (`cmd+shift+,`) and restart nvim.
3. Commit the two files to keep the scheme.

| Command | Does |
|---|---|
| `change_theme` | pick the scheme for the mode macOS is in now |
| `change_theme dark` / `change_theme light` | pick the scheme for that mode |

To preview schemes before picking one: the [Tinted Gallery](https://tinted-theming.github.io/tinted-gallery/)
shows them all.

Config
---
| File | Contains |
|---|---|
| `config/nvim/lua/user/base16-vim/schemes.lua` | the scheme nvim loads in each mode, written by `change_theme` |
| `config/nvim/lua/user/base16-vim/config.lua` | loads the scheme for `'background'` at start and on every change |
| `config/ghostty/themes/base16-dark`, `base16-light` | Ghostty's colours for each mode, generated by `change_theme` from the same schemes |
| `config/ghostty/config` | `theme = light:base16-light,dark:base16-dark` |
| `zsh/functions/theme.zsh` | `change_theme` |

To look out for
---
- `change_theme` needs nvim's plugins installed, because the scheme list comes from tinted-vim.
- Don't edit `themes/base16-*` by hand: the next `change_theme` overwrites them.
- A scheme whose file `change_theme` can't read (tinted-vim changed its format) changes nothing: the new theme
  is written next to the live one and replaces it only with all 22 colours in it.
- `change_theme light` refuses a scheme with a dark background, and `dark` one with a light background: nvim
  tells the modes apart by the background's brightness, so it would load the other mode's scheme.
- Until a light scheme is picked, `themes/base16-light` is a copy of `base16-dark` and `schemes.lua` names
  the dark scheme for both modes, since `change_theme light` won't write a dark one.
- An nvim started in light mode can show the dark scheme for a moment, until the terminal's answer comes in.
- nvim over SSH, or in a terminal that doesn't report theme changes, keeps the scheme it started with.
- Nothing may set `'background'` in nvim's config: setting it by hand turns nvim's own detection off.
- The GIFs (`make_gifs`) always use the dark theme, so they look the same whichever mode macOS is in.

Decisions
---
- **ANSI colour names everywhere else, never hex**, so a new scheme reaches every tool through the terminal's
  16 colours without touching their config.
- **nvim follows the terminal's background, not macOS directly**: Ghostty already knows the mode, and nvim
  already asks the terminal for its background, so no plugin or polling of `defaults read` is needed, and an
  nvim shows the scheme that matches the window it's in.
- **Plain Source Code Pro, not a patched Nerd Font**: Ghostty's built-in symbol font draws the icons.
